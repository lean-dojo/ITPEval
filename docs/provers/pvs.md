# PVS

PVS is a specification language and theorem prover. A theory can define a system, state what its functions must do, and prove those properties. [Project documentation](https://pvs.csl.sri.com/)

## How proof checking works

PVS uses classical higher-order logic with predicate subtypes and dependent types. A predicate subtype narrows a type by a condition. For example, the result type `{x: int | x = 2*n}` specifies which integer a function is allowed to return for its input `n`.

When such a restriction needs proof, the typechecker generates a type-correctness condition, or TCC. The PVS theorem prover works with sequents, which show assumptions and goals. Strategies such as `grind` can simplify expressions and apply decision procedures. A proof run can check both an explicit lemma and the TCCs generated by its theory. [PVS System Guide, typechecking and proof obligations](https://pvs.csl.sri.com/doc/pvs-system-guide.pdf)

## Read a proof

In the imported theory `base`, `bump(x: int): int = x + 1` defines a function that adds one to an integer. [Open base.pvs](../../itpeval/tests/fixtures/projects/pvs/library/base.pvs)

<figure class="proof-listing" data-listing="pvs" data-proof="(grind)" markdown="1">

<figcaption markdown="span"><strong>PVS</strong> [sample.pvs](../../itpeval/tests/fixtures/projects/pvs/library/sample.pvs)</figcaption>

```pvs
% ProofLite runs the command in the proof block for step.
  step: LEMMA FORALL (x: int): bump(x) > x
  %|- step : PROOF
  %|- (grind)
  %|- QED
```

</figure>

**The claim.** The line `step: LEMMA FORALL (x: int): bump(x) > x` names the lemma and states that bumping any integer produces a greater integer.

**The proof.** In this file the ProofLite script for `step` is between `%|- step : PROOF` and `%|- QED`. Its command is `(grind)`. The later script in the full file proves a separate obligation for `twice`.

By definition, `bump(x)` equals `x + 1`, and adding one makes any integer larger. The proof strategy discharges the goal using the definitions and arithmetic. Typechecking the statement alone precedes this proof run.

<details markdown="1">
<summary>What does twice_TCC1 require in this theory?</summary>

The body of `twice(x)` returns `x + x`. Its declared result type requires the returned value to equal `2 * x`. The generated condition establishes that the body satisfies this restriction.

</details>

## Use your own project

Use a `.pvs` theory and keep the imported source theories in the PVS context. For an ITPEval proof-completion task, put the target command in the file’s inline ProofLite block and name the TCCs that must be proved.

Check a source file with `itpeval eval --prover pvs --file PATH`. [Check a file you already have](../guides/work-with-a-library.md#check-a-file-you-already-have)

For extraction, choose an entrypoint relative to the project root.

```bash
# Replace the directory and entrypoint with the paths for your project.
itpeval dataset pvs --project ./my-project \
  --entrypoint sample.pvs --output ./dataset
```

For a prepared project, pass `--lock PATH` in place of `pvs --project ./my-project`. [Configure a project](../guides/environment-manifest.md)

## Libraries

PVS loads its prelude automatically. Additional distributed theories and the NASA PVS Library can be imported as needed.

- [Prelude](https://github.com/SRI-CSL/PVS/blob/master/lib/prelude.pvs) — theories loaded by PVS at startup.
- [PVS libraries](https://github.com/SRI-CSL/PVS/tree/master/lib) — theories distributed with PVS, including finite sets.
- [NASA PVS Library](https://github.com/nasa/pvslib) — research libraries for areas including analysis and geometry.

### Build and check a library

Use the prelude supplied by PVS. Set up external libraries such as NASALib using their matching PVS release and library search paths. To replay proofs across a collection, run `provethem` with the project's library list. For NASALib, use its `prove-all` script. [NASALib installation and batch scripts](https://github.com/nasa/pvslib#scripts)

```bash
# Run from the directory containing the libraries listed in libraries.txt.
provethem libraries.txt

# Check a selected theory with PVS's batch proof driver through ITPEval.
itpeval eval --prover pvs --task-dir ./my-project --task-file top.pvs
```

Keep the source context, imported theories and proof files together. The adapter creates a fresh working context and calls `proveit` on the selected file. Check its summary for proof and type-correctness condition (TCC) coverage.

### Extract a library

The bundled example imports `bridge` and a finite-sets helper from the PVS distribution, instantiated at `int`. The extractor reads the typechecked theories and their obligations.

After installation, run the Python examples in order. [Installation](../runtime/toolchains.md)

```python
from pathlib import Path

from itpeval.cli.lib import default_prefix
from itpeval.corpus.datasets import export_dataset
from itpeval.corpus.example import LIBRARY
from itpeval.corpus.storage import read_jsonl
from itpeval.environments import prepare_project

# Prepare the source files and the prover that will load them.
project = LIBRARY / "pvs/library"
output = Path("build/library/pvs")
library = prepare_project("pvs", project, prefix=default_prefix(), cache=Path("build/itpeval-cache"))
# Export the records and print the files the extractor actually processed.
bundle, premises = export_dataset(library, "sample.pvs", output)
print("Processed files:", bundle.report["succeeded"])
```

### Find a declaration in the export

Join the declaration to its premise record using `declaration_id`.

```python
# Find this declaration in the export and read the status supplied by the prover.
rows = read_jsonl(bundle.path / "declarations.jsonl")
target = next(row for row in rows if row["name"] == "sample.step")
print(target["name"], target["checking_status"])
print(target["statement"])
```

The checker status is `typechecked`. PVS typechecked the statement. To establish the lemma, run its proof and discharge the generated type-correctness condition below.

### Check the extracted library lemma

The proof of `step` uses the imported definition of `bump`. The project also requires `twice_TCC1`, generated by the result type of `twice`. [Completion manifest](../../itpeval/tests/fixtures/projects/pvs/library/completion.json)

```python
from itpeval.backends.projects import build_task
from itpeval.verification import verify

# Load the proof slot for step and run its candidate against the same imports.
task = build_task(library)
result = verify(task, "(grind)", prepared=library)
print(result.checker_outcome)
# Inspect the verdict for step and for the subtype obligation separately.
print(dict(result.obligations))
```

PVS returns `accepted` and reports both `step` and `twice_TCC1` as `discharged`.

## Proof completion

Fill the ProofLite command for the lemma that doubling an integer gives twice its value. A separate script handles the generated subtype obligation `twice_TCC1`. Replace the underlined fragment.

```pvs
% The ProofLite command between PROOF and QED must close the lemma.
itpeval_target: LEMMA FORALL (n: int): twice(n) = 2*n
  %|- itpeval_target : PROOF
  %|- (skip)
  %|- QED
```

</figure>

### Complete it yourself in VS Code

```bash
# Create a working copy with a failing proof and a task for the native checker.
itpeval practice pvs
code build/practice/pvs
```

1. Open `hello.pvs` and run **Terminal → Run Task → ITPEval: Check saved proof**. skip leaves the lemma open even though its statement typechecks.
2. Find `(skip)` inside `itpeval_target` and replace it with `(grind)`. grind discharges the arithmetic goal. ITPEval also requires the proof summary to report the subtype obligation discharged.
3. Save and rerun the task. The terminal prints `pvs · itpeval_target · accepted`. [Completed source](../../itpeval/tests/fixtures/projects/pvs/completion/hello.pvs)

VSCode-PVS provides a proof explorer and an interactive sequent view with a compatible PVS installation. [VSCode-PVS](https://shemesh.larc.nasa.gov/fm/VSCode-PVS/)

From Python, run a reviewed strategy command, change subgoal focus, or save the command history. [Branch and restore a PVS proof](../runtime/hol-and-pvs-interaction.md#branch-and-restore-a-pvs-proof)
